2 Main Pruning & Quantization Components, Hyperparameters & Tricks

havu/experiments/E043_dsv41_real_pruning

1. Lossless Engram Row Frequency Pruning 189 GiB → 64 GiB

  • Problem: The 2-layer Engram n-gram table (layers 1 & 14, 384M × 1280 FP8 + scales) is 188.8 GiB in pinned host RAM—exceeding Kaggle's 173 GiB cgroup limit.
  • Census (engram_census.py): Replayed 10,001 Flash-1017 tool rollouts (251.8M tokens, 6.04B lookups/layer). Only 58.2% of rows (110 GiB) are ever touched; top rows hit >64K times carry 39% of all lookups.
  • Mask Selection: Kept the top 34% most frequent rows globally (engram_top64gib.json: 35% on layer 1, 32% on layer 14 = 64.0 GiB, or 15.8 GiB/rank across 4 GPUs).
  • Remapping Trick (apply_compact_engram.py): Added int32 tensor layers.{1,14}.engram.embed_tokens.row_map (2.9 GiB) mapping kept rows to 0..K-1 and dropped rows to -1 (read as zero vector before $W_{kv}$).
  • Result: 97.6% calibration hit rate, 94.0% eval hit rate (~100% on prompt/grids). +0.00% to +0.04% NLL change (lossless).

2. Protected Contribution Expert Pruning 384 → 128 Experts

  • Why Plain REAP Failed: Plain REAP ranks experts by conditional mean amplitude when selected ($\mathbb{E}[\|y_e\| \mid e \in \text{top-}6]$). It kept rare, high-norm outlier experts covering only 32% of routing traffic at E64. Iterative pruning also lost to one-shot selection (0.879 vs 0.822 NLL at E72).
  • Base Rule (contrib_dec): Recorded native weighted expert output L2 norms $a_{t,e} = r_{t,e}\|\text{Expert}_e(x_t)\|_2$ over 10.04M calibration tokens. Summed over all tokens on encoder layers 0..19 and over model-generated tokens only on decoder layers 20..39.
  • Critical Trick — Tool-Block Upweighting (w = 10): DSML tool-call blocks (</think> token 128822 to EOS) are only ~6% of tokens. Without upweighting (w=0), pruned models forget how to close <｜DSML｜function_calls> tags. Scoring with $\text{Score} = \text{Contrib}_{\text{dec}} + 9 \times \text{Contrib}_{\text{tool\_block}}$ (keep_contrib_dec_sp0_w10_e128.npy) preserves >95% of tool-block contribution and achieves 0 format failures across 334 eval attempts.

3. Per-Expert 2-Bit Asymmetric GPTQ percdamp = 1.0

  • Selective Quantization: Attention, router (sliced to 128 rows), shared MXFP8 expert, norms, embeddings, LM head, and Engram remain untouched. Only the 40 × 128 = 5,120 routed experts are quantized to uint2:
    • w1, w3 (gate/up, [2304, 5120]): uint2, group size g13 = 128, BF16 scale, uint2 zero-point.
    • w2 (down, [5120, 2304]): uint2, group size g2 = 64, BF16 scale, uint2 zero-point.
  • Pruned-Mask Calibration: 61 tool rollouts (1.42M tokens, 10% rows = 142,138 vectors) replayed under the E128 mask. w2 Hessian $H_2 = u^\top u$ uses quantized w13 outputs with native V4.1 clamps: $u = r_e \cdot \text{SiLU}(\min(g, 10)) \odot \text{clamp}(u_{\text{up}}, -10, 10)$.
  • Critical Hyperparameter (--percdamp 1.0): Each expert sees only ~3.4K rows for a 5,120-dim input ($N < d$). Standard percdamp=0.01 overfits the Hessian and loses to RTN on held-out tokens (15.0% vs 13.2%). Setting percdamp=1.0 slashes relative output error to 2.5% on w13 (vs 10.9% RTN) and 5.5% on w2 (vs 12.7% RTN).

4. Harness, Multi-Test & Serving Tricks +3.7 pp Pass@1

  • sub80s40 + Minimal Header: 80k total output cap, 40k soft wrap-up budget, 64k/turn, effort=50 (low), T=1.0.
  • --token-exact (E046): Passes exact sampled token IDs across turns instead of re-tokenizing text (1 in 8 turns samples non-canonically), keeping prefix cache hits at 96.7%.
  • --multi-test --multi-budget 0.5 (E046 Run 7): Solves all test pairs of a task in one shared trajectory, lifting Task Pass@1 to 73.7% and Pass@2 to 84.6% while cutting tokens by -17% overall (-30% on multi-test tasks).
  • auto_repair.py (E052): Catches identifier errors, rewrites unique OSA edit-distance $\le 2$ typos ([auto-corrected: coms -> comps]), and re-runs once—lifting Task Pass@1 to 76.5%.
  • Candidate B (E051 + E054 + E056): 32 GiB CPU KV offload (3.4–4.0× tok/s at high concurrency) + dsv41_indexer.py grid-stride context skip (-6.5% decode step time, bit-identical logits).
Root Cause of Pruned Model Errors — BPE Sub-Word Split-Mixing (analysis/typos/REPORT.md): Expert pruning (not 2-bit quantization) increases Python identifier errors from 0.23% to 8.22% in E128 (coms for comps, scpy for scipy, dequeue for deque, dbool for dtype=bool). Why? 94% of typos occur in multi-token identifiers and 88% start strictly at a word-internal alphanumeric continuation (WIC-alnum) token boundary. Because BPE tokenizes comps after a space as ['Ġcomp', 's'] (0 typos in 5,971 uses!) but tokenizes =comps after punctuation as ['=', 'com', 'ps'] (15%–81% typo rate!), the pruned model emits the first piece of the punctuation split (com) and the continuation of the space split (s) → coms. Upweighting WIC-alnum tokens during SFT directly heals this transition!

1. Path A (Recommended — Lossless Pre-2-Bit Rebuild + Exact BF16 Decode): In the 2-bit HF repo (chankhavu/DeepSeek-V4.1-Flash-1017-arc-tool-E128-2bit), every non-expert tensor is already byte-identical to the base model, and e043_manifest.json records the exact 128 kept expert IDs per layer (keep_contrib_dec_sp0_w10_e128.npy). To decode the native MXFP4 routed experts and MXFP8 dense/shared-expert weights into standard torch.bfloat16 tensors (362.4 GB for all 5,120 experts + 18.5 GB backbone = ~381 GB total in BF16):

import torch

E2M1 = torch.tensor([0.0, 0.5, 1.0, 1.5, 2.0, 3.0, 4.0, 6.0], dtype=torch.float32)

def mxfp4_to_bf16(weight: torch.Tensor, scale: torch.Tensor, device="cuda") -> torch.Tensor:
    """Bit-exact decode of DeepSeek-V4.1 MXFP4 expert weight [N, K//2] + UE8M0 scale [N, K//32] -> BF16 [N, K]."""
    w = weight.to(device).view(torch.uint8)
    codes = torch.stack([w & 0x0F, w >> 4], dim=-1).reshape(*w.shape[:-1], w.shape[-1] * 2).long()
    mag = E2M1.to(device)[codes & 7]
    val = torch.where((codes & 8) != 0, -mag, mag)
    s = scale.to(device).view(torch.uint8).to(torch.int32)
    return (val * torch.exp2((s - 127).float()).repeat_interleave(32, dim=-1)).to(torch.bfloat16)

def mxfp8_to_bf16(weight: torch.Tensor, scale: torch.Tensor, device="cuda") -> torch.Tensor:
    """Bit-exact decode of DeepSeek-V4.1 FP8 (E4M3fn + UE8M0 scale) dense/shared-expert weight -> BF16 [N, K]."""
    w = weight.to(device).view(torch.float8_e4m3fn).to(torch.float32)
    s = scale.to(device).view(torch.uint8).to(torch.int32)
    return (w * torch.exp2((s - 127).float()).repeat_interleave(32, dim=-1)).to(torch.bfloat16)

Path B: Direct Unpacking / Dequantization of the 2-Bit gptq/layer_LL.safetensors Weights to BF16

If starting strictly from the 131.1 GB 2-bit checkpoint (chankhavu/DeepSeek-V4.1-Flash-1017-arc-tool-E128-2bit), each gptq/layer_{00..39}.safetensors stores e{0..127}.{w1,w2,w3}.{q,s,z} where q is int32 [N, K//16] (16 × uint2 codes packed LSB-first along $K$), s is bfloat16 [N, K//group] (group=128 for w1/w3, group=64 for w2), and z is int32 [N//16, K//group] (16 × uint2 zero-points packed LSB-first along $N$):

from pathlib import Path
import torch
from safetensors import safe_open

SHIFTS = torch.arange(0, 32, 2, dtype=torch.int32)  # 16 x uint2 per int32, LSB first

def unpack_uint2(packed_int32: torch.Tensor) -> torch.Tensor:
    shifts = SHIFTS.to(packed_int32.device)
    return ((packed_int32.unsqueeze(-1) >> shifts) & 3).reshape(*packed_int32.shape[:-1], -1)

def dequant_gptq_expert_tensor(q: torch.Tensor, s: torch.Tensor, z: torch.Tensor, group: int) -> torch.Tensor:
    """Unpacks Humming packed 2-bit (q, s, z) into exact BF16 [N, K] weight matrix: W = (q - z) * s."""
    q_u2 = unpack_uint2(q).to(torch.float32)                                  # [N, K]
    z_u2 = unpack_uint2(z.T.contiguous()).T.contiguous().to(torch.float32)    # [N, K // group]
    s_f32 = s.to(torch.float32)                                               # [N, K // group]
    w_f32 = (q_u2 - z_u2.repeat_interleave(group, dim=-1)) * s_f32.repeat_interleave(group, dim=-1)
    return w_f32.to(torch.bfloat16)

def unquantize_layer_experts(gptq_dir: str, layer_idx: int, n_experts: int = 128, device: str = "cuda"):
    path = Path(gptq_dir) / f"layer_{layer_idx:02d}.safetensors"
    bf16_experts = {}
    with safe_open(str(path), framework="pt", device=device) as f:
        for e in range(n_experts):
            for proj, group in (("w1", 128), ("w3", 128), ("w2", 64)):
                w_bf16 = dequant_gptq_expert_tensor(
                    f.get_tensor(f"e{e}.{proj}.q"),
                    f.get_tensor(f"e{e}.{proj}.s"),
                    f.get_tensor(f"e{e}.{proj}.z"),
                    group,
                )
                bf16_experts[f"layers.{layer_idx}.ffn.experts.{e}.{proj}.weight"] = w_bf16.cpu()
    return bf16_experts

4 SFT Recipes on Pruned DeepSeek E128 & Post-SFT 2-Bit Re-Quantization

Strategy 1 (Fastest & Highest ROI): "Healing LoRA" on Attention + Shared Experts No GPTQ Needed!

  • Key Architectural Insight: In Tool E128 2-bit, all attention projections (q_a_proj, q_b_proj, kv_a_proj_with_mqa, kv_b_proj, o_proj), routers, and shared experts (shared_experts.w1/w2/w3) are NOT 2-bit quantized—they run in native BF16/FP8!
  • Zero Re-Quantization Path: Keep the 128 routed experts frozen (in BF16 during FSDP2 forward/backward) and train LoRA (r=32, alpha=64, lr=1e-4) on attention + shared experts. Merge the trained LoRA directly into the dense/shared shards and keep the existing gptq/layer_00..39.safetensors untouched!
  • WIC-alnum Loss Upweighting (×10–20): Apply a ×10–20 loss multiplier on word-internal alphanumeric continuation tokens (WIC-alnum, ~6% of code tokens) and DSML tags on 1.5k–3k zero-typo Flash-1017 winning tool traces.

Strategy 2: Full / Routed-Expert SFT on 8×B200 + 2-Bit GPTQ Re-Export Full Adaptation

  • 8×B200 Memory Layout (1,440 GB HBM3e):
    • BF16 weights (381 GB total across 8 GPUs): 47.6 GB / GPU.
    • BF16 gradients: 47.6 GB / GPU.
    • 8-bit AdamW or CPU-offloaded optimizer states: ~24 GB / GPU.
    • Leaves ~60 GB / GPU for activation checkpointing at 32k–64k context!
  • Hyperparameters (train_full_sft.py): lr = 5e-6 to 1e-5, cosine schedule, warmup_ratio = 0.05, global_batch_size = 16–32, freeze_engram = True.
  • Mandatory Post-SFT 2-Bit GPTQ Re-Quantization: Because 4×L4 only fits 2-bit routed experts, run gptq_experts.py --percdamp 1.0 --bits13 2 --bits2 2 --group13 128 --group2 64 across 8 GPUs (5 layers/GPU in parallel = ~8 min) followed by make_lowbit_export.py.
