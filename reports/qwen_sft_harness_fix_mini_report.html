2 What Was Fixed in the Evaluation Harness (In Plain English)

Why Full SFT Jumped from 40.76% → 55.00% Official Kaggle Pass@2
Why did Full SFT benefit so much more from these fixes than LoRA?
Full SFT updated 100% of Qwen's 26.9B parameters (reaching a lower validation loss of 0.7549 vs. LoRA's 0.7627). Because Full SFT adapted more strongly to the training format, it was hurt much more when our old evaluation harness had prompt mismatches, mid-code cutoffs, and premature unverified exits. Fixing these 5 issues immediately unlocked Full SFT's true performance.

1. Restored Qwen's Built-In tier=xhigh System Sentence

What was broken: Qwen3.8-27B was pre-trained by Alibaba with a specific magic sentence at the very start of the system prompt: "Reasoning effort is set to xhigh. Please think carefully through the task...". Our old eval accidentally replaced that sentence with a custom string ("Reasoning Effort: Minimal").

The fix: We restored Qwen's exact pre-trained tier=xhigh sentence at the top of the system prompt while keeping the brief-code instruction at the bottom of the tool block, eliminating the system prompt mismatch.

2. Capped Single-Turn Thinking at 8k + 2-Stage Graceful Nudge

What was broken: The old eval allowed the model to think for up to 32,000 tokens in a single turn without running any Python code. On hard puzzles, the model got stuck over-thinking in <think>...</think> and burned half its budget before testing a single line of Python.

The fix: When thinking hits 8,192 tokens, Stage 1 appends a gentle wrap-up note ("...Wrapping up my reasoning cleanly so I can test in Python.\n</think>\n\n") and gives 2,048 grace tokens. If it still doesn't call a tool, Stage 2 opens <tool_call>\n<function=run_python> directly so it immediately writes code.

3. Fixed Mid-<tool_call> Python Code Truncation

What was broken: When a turn hit the token cap, the old harness checked if "<tool_call>" not in text:. If the model finished </think> near token 8,000 and was halfway through writing Python code inside <tool_call> when token 8,192 hit, the harness sent the half-written code to Python, causing an instant SyntaxError.

The fix: We now check whether the XML tool call is actually closed ("</tool_call>" in text). If the model is cut off mid-code, we grant 2,048 grace tokens so it finishes writing its Python script cleanly.

4. One-Time Rejection of Unverified Submissions (verify_submit)

What was broken: If the model called submit_answer(solve(test_input)) with a buggy solve() function that failed on the training examples, the old harness accepted the grid immediately and ended the attempt—throwing away all remaining budget.

The fix: When submit_answer is called, the harness automatically tests the rule on all training pairs. If it fails on any training pair, the harness rejects the submission once and tells the model how many training pairs matched so it can keep debugging in Python (while keeping the grid saved as a backup).

5. Salvaging Working Session Code Before Forced Guesses

What was broken: When an attempt ran out of budget without calling submit_answer, the old harness forced a last-second 1-line submit_answer guess before checking Python memory, which overwrote working functions the model had already defined.

The fix: At timeout, we first check live Python memory for answer, solve(test_input), or any helper function (accepting either Python lists or NumPy arrays) that reproduces the training pairs, and only ask for a forced last-second guess if no working function exists.
