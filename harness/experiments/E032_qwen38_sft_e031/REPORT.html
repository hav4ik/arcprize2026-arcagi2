E032: Qwen3.8-27B distilled from DeepSeek-Flash-1017 tool traces

A second LoRA SFT of Qwen3.8-27B, this time on 1,900 complete, correct and train-verified multi-turn tool rollouts from DeepSeek-V4.1-Flash-1017 (E031). It fixes E028’s main flaw: those sequences were cut at 64K, so the model never saw a teacher finish under budget pressure. This report covers the data, training, export, serving checks, Kaggle candidates, and the evaluation so far.

Teacher data: E031 rollouts

The same 2,500 pairs as E028’s training set (1,070 official ARC-AGI-2 training pairs plus 1,430 NVARC synthetic nvarc_b0 pairs), re-collected with the new DeepSeek model. DeepSeek’s API name deepseek-flash has served V4.1-Flash-1017 since about 2026-10-17, and the original V4.1-Flash that produced E025 is retired. The config is E030’s cheapest one within 5 pp of the best on eval:

  • Harness: run_deepseek_tools.py (persistent-v6), grid mode, low effort, prompt lean2sub, tools run_python and submit_answer, session fallback, lenient parse.
  • Budget: soft target 20k with the “strong” wording past it, hard limit 60k, notes on every tool output, “Budget nearly spent” at 45k, and a turns-left note at 5 turns.
  • System message: --effort-header minimal, a custom header we wrote, since DeepSeek has no such tier: “Reasoning Effort: Minimal. Keep your thinking short and terse… submit as soon as the rule reproduces every training pair.”
  • Left out: no task summary and no helpers. --train-check records whether the answer program reproduces every training pair, host-side and without model tokens.

Why only correct traces

Two read-only sub-agent audits read 85 incorrect traces end to end, plus scripted checks over all 469.

Incorrect groupnWhat happenedVerdict
passed train check, wrong on test256Clean process: every pair verified, no hard-coding. The rule fits training but not the test; often the model saw an odd test feature and dismissed it.usable, not needed
submitted with a failing training pair19298% submitted right after the 20k note, with hand-typed grids, test-only parameters or copies of the test input. Only 1–2 of 12 made a sensible best guess.harmful
never answered22Long thinking loops; one spent 60k tokens in a single turn with no tool calls.harmful
correct but failed train check124About a third are hand-typed answers that happened to be right.dropped

The recovery moves worth learning (diff a failing check, fix, re-verify; fix a traceback; re-print a misread grid) also appear in the correct traces, so dropping the incorrect ones loses little. The audit also found that the Minimal header cuts the final check of the test input. Median thinking after the last passing check is 38 characters for E031 vs 803 for E025, but E025’s prompt explicitly required that check, so the comparison is confounded.

Export, quantization, serving checks

  • Export: save_weights_external plus signed URLs: 3.86 GB adapter. The API key never left this machine.
  • Merge: build_hf_model into Qwen3.8-27B BF16 in 117 s, 52 GB.
  • Block FP8 in the official Qwen/Qwen3.8-27B-FP8 layout: e4m3 128×128 weight blocks, BF16 weight_scale_inv, dynamic activations. Took 18 s, 30.87 GB, max per-tensor relative error 2.65%. quantization_config is identical to the official one. This is E028 v2’s audited recipe.
  • Serving: SGLang 0.5.20, one server per GPU, FP8 KV cache, radix cache, 939k KV tokens per RTX PRO 6000. Includes E028’s tool-JSON patch (stock SGLang adds 22 tokens of tool JSON).
  • Prompt format: every server reports prompt token counts identical to the training render (12/12 per model, re-checked on every box and after every restart).
  • Parity, served vs Tinker: trained-token NLL is within +0.002 to +0.006 for E032 and +0.001 to +0.006 for base. The same offset in both points to the FP8 KV cache. The SFT gain of about −0.10 NLL vs base is preserved when served.

  • The notebook reproduces the RTX eval. On these 48 pairs, E032 solved 15 at the 60k cap on the RTX boxes, 7 within 29k, and 6 within the tokens each paced attempt actually got. That is exactly the paced result, so the loss is about finishing within the budget, not about the Kaggle port.
  • E032 rarely finishes inside its share. It learned a 20k soft target and a 60k hard stop, the notes still say 60k, and on RTX its attempts average 37k tokens. On Kaggle the share is about 29k, and time cuts bring it to 21.8k on average.
  • It is also slower on the same box: 152 vs about 210 tok/s for base. It makes more, shorter requests (1.8k generated tokens per request vs 3.0k), and each re-prefills up to 1.5k tokens because of the cache’s 1,568-token blocks.

Reasoning-effort tier (Qwen system line), E032

Qwen3.8 has three tiers (xhigh, medium = no line, low), and the template rejects anything else. Like DeepSeek’s invented Minimal header, we wrote a minimal tier, served through a chat template with one added branch: “Reasoning effort is set to minimal. Keep your thinking short and terse: brief notes, not full sentences. Test ideas with small code experiments instead of long deliberation, and submit as soon as the rule reproduces every training pair.” It replaces the xhigh line that E032 was trained with, and the E031 header still follows the tools block. The sentence is byte-identical to Kaggle candidate minimal v2.

Incidents and lessons

  • Early-loss readout: with short, varied sequences, per-batch NLL hides a −0.05 gain. Use the paired compute_logprobs check on fixed sequences. The run was paused needlessly at step 25 for about a minute, costing at most one discarded step.
  • HF storage: the org hit its 100 GB private limit, which is why E028’s block-FP8 upload stopped at 8/18 shards. That went unnoticed until a vLLM load succeeded silently with missing shards. Every upload is now verified against the index.
  • Kaggle downloads outside Kaggle: whole-version downloads return 404, but per-file kagglehub.model_download(path=…) works.
  • Box access: some Vast hosts expose SSH only on a direct port. One host (Czechia) never got ports and was replaced. A box-to-box key append ran onto an existing line of authorized_keys because the file had no trailing newline. The user’s key still works, and the repair was not attempted further.
  • Wording drift: the minimal sentence was briefly swapped between the eval template and the Kaggle harness. It is now frozen and checked byte for byte.

Either way, compare against base v4b at Kaggle pace, not against base in the teacher’s harness.
  • Interface: test the student without the test-check suppression the Minimal header causes. For example, re-collect teacher traces with a test-difference check in the prompt and with helpers (AGENTS.md asks for --helpers).
