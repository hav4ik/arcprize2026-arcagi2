## 2. Local Kaggle replica protocol (E055)
1. One rented Runpod 4×L4 pod (72 W, same power limit as Kaggle's, from the B smoke), GPU util 0.938 so the KV pool
   (1,556,850 tokens) equals Kaggle's (1,554,183 at 0.945).
2. The exact frozen Kaggle code (hash-checked kit), run through the notebook's cells (`/root/podrun.sh` + `local_run.py`).
3. Workload: 120 public ARC-AGI-2 eval tasks ×2 = 240 tasks / 344 pairs (hidden-set sized). `evalx2t_s2026`: the second
   copy is rotated/flipped and colour-permuted (no shared prefix cache). V5's replica used identical copies.
4. Kaggle's deadlines (stop-new 10.83 h, force 11.17 h, hard stop 11.5 h); B32 and V6 started them 600 s earlier for
   Kaggle's slower startup.
5. Raw score: the submission the run wrote, scored task-weighted (each task = fraction of its pairs correct, averaged
   over tasks; the LB metric) against local solutions.
6. Kaggle-clock score (`toolkit/replica_report.py`): the pod timeline stretched by Kaggle's measured slowdown (prefill
   ×1.45, decode ×0.94, ≈ ×1.1 overall, from a Kaggle-bench-vs-pod twin run of V6 settings) and attempts finishing after
   Kaggle's force deadline dropped.
7. A run must go past the Kaggle-clock force deadline (pod hour ~9.7-9.9), so a replica takes ~10-11 h.

## 5. Validation of B32 beyond the replica
- **Kaggle smoke** (B16 = Version 1, user-approved, ~21 min, ~0.75 h quota at 2× billing): E046 CHECK OK with all pinned
  hashes, 16-file overlay, KV 1,554,183, the offload line, 6/6 pairs submitted, valid submission. Host: anon 10.8 +
  shmem 106.9 GiB at start vs the 173 GiB cgroup (page cache fills the rest, reclaimable); VM 188.7 GiB; GPUs 72 W limit;
  `PYTORCH_CUDA_ALLOC_CONF` unset in Kaggle's image; /kaggle/working 19.5 GiB free, /tmp 1 TB (E056 README).
- **E056 (4090):** the combined kit installs through the notebook's own cells (16/16 shas), byte-level offload parity
  8/8 on all ranks with the indexer skip on, late-phase A/B tie (618 vs 617 tok/s).
- **E051 late-phase replays (4090):** without offload ~95 tok/s at 36-48 heavy streams (full thrash); with offload
  874-971 tok/s. 16 GiB collapses at 56 heavy streams (171-216 tok/s, host hits ~0) in v1 and v2: the host-pool cliff.
  32 GiB clears 64 streams (971 tok/s). Late throughput plateaus at ~970 (≈38 heavy streams fit on the GPU pool).
- **E057b stress (4090, 90 heaviest tasks, real solver, 16 GiB, 80 min):** 56 vs 64 workers: 765 vs 774 tok/s, 0 vs 0
  preemptions, peak in-flight context 2.68M vs 2.62M (cliff ~4.8M), host memory ≤ 49% of the box. The gate shrinks
  in-flight attempts as contexts grow (55 → 39).
- **Memory:** pinned host buffers round up to a power of two per rank, so pool sizes are 16 or 32 GiB exactly. Worker
  anon growth slows to ~0.1 GiB/h per worker; projected Kaggle peak at 12 h ~141-145 GiB with 32 GiB.
- **Pending: E059 restart-under-load** (forced TP1 worker death at +1.5 h, 2-s memory sampling): 32 GiB on L4 hegn
  (kill ~09:52 PDT), 16 GiB on 4090 57983124. The check: old server memory (Engram shm + pinned pool, ~123 GiB) must be
  released before the new server allocates, or a restart could exceed Kaggle's 173 GiB.

## 6. Packaging
- Pinned code (what the replica ran): `kaggle/dsv41_tools/pinned_candb/` (solver 77fe80a3, harness 882c817f,
  train_check 8fe36175, auto_repair). Shipping train_check too avoids the kit's older 44c4d210.
- `build_frozen_mt.py` checks every pinned file's imports against the Kaggle kit (`check_imports`): the live harness
  (E058 text+image prompts) imports `grid_image.deepseek_cell`, which the kit lacks, so a notebook built from live code
  would have failed every attempt on Kaggle.
- New builder options: `--admit-max-waiting`, `--smoke-minutes 30` (commit-run smoke ends within 30 min: deadlines,
  host/GPU/disk sampler, report cell), `--train-check`, `--pins-dataset` (no base64: pinned files in a small private
  dataset + the readable `cells/cell0b_pins.py`).
- Built locally, not pushed: `out/nb_candb32` (B32, base64 cell like Version 1), `out/nb_candbp_w56` and
  `out/nb_candbp_w64` (B+ variants with the pins dataset `out/pins_dsv41-candbp-pins`).
- Shared data: the B32 replica (traces, logs, workload, report, code) is the private HF dataset
  `livobereshka/arc-agi2-dsv41-e128-candb32-replica`.

## 8. Operations notes
- Kaggle: 4×L4 sessions count 2× against the weekly quota; every Kaggle run needs the user's OK; smokes ≤ 30 min.
- Vast: a stopped instance loses its GPUs (5 of 5 restart attempts failed); keep a box running if more tests may follow.
- Runpod L4s are the scarce resource; use them for full replicas, and 4090s for A/B tests, parity and packaging.
