This report collects every model and harness experiment we have run on ARC-AGI-2 so far. Models: DeepSeek V4.1-Flash, its replacement V4.1-Flash-1017 (served as `deepseek-flash` from 2026-10-17) and V4-Pro (DeepSeek API); Qwen3.8-27B (NVFP4 and FP8 checkpoints on self-hosted SGLang/vLLM, on Kaggle 4×L4 and on rented boxes, INT4/AWQ variants, and a LoRA SFT on DeepSeek tool rollouts) and Qwen3.6-35B-A3B; MiniCPM-V-4.7-35B-A3B and LFM2.5-24B-A2B (self-hosted); Nemotron 3.5 Lightning and Nemotron 3 Super 120B (OpenRouter) and Nemotron-3.5-Bolt (self-hosted, 2-bit experts). E025's DeepSeek rollouts on training tasks (SFT data for E028) are not evaluations and are left out. Every number below is recomputed from `evals/results/*.jsonl`, `kaggle/runs/` and E027's solver summaries (`experiments/E027_l4_throughput/`) by `reports/build_report.py`. ## Scoring convention

- **Primary metric: Kaggle score (pair-weighted).** The ARC Prize 2026 ARC-AGI-2 competition page on Kaggle allows 2 attempts per test input; a test output scores 1 if either attempt matches exactly, else 0, and "The final score is the average across all task test outputs". So the Kaggle score = solved test outputs / all test outputs (167 on the public eval set), and a task with 2–3 test inputs counts 2–3 times. All headline numbers, best-value shading, sorting, charts and paired Δs use this metric because it is what the competition scores.
- **Secondary metric: ARC Prize task-weighted.** The ARC Prize benchmarking harness (`arc-agi-benchmarking`, `scoring.py`) scores each task as the fraction of its test pairs solved and averages over the 120 tasks. ARC Prize's published leaderboard numbers use this convention, so it is shown in smaller muted columns and quoted in parentheses where we compare with ARC Prize's numbers. The two differ only through the 45 tasks with more than one test input; for Table 1 runs the gap is at most 2.3 pp, and Kaggle is the lower of the two in 60 of 74 pass@1/pass@2 values (Appendix).
- **Full set** = the official ARC-AGI-2 public evaluation set from github.com/arcprize/ARC-AGI-2 (120 tasks / 167 test pairs). This is the public evaluation set, not the hidden Kaggle test set (240 tasks / 259 pairs) and not ARC Prize's semi-private set.
- **pass@1** = mean over attempts (samples) of the single-attempt score, ± sd over samples. **pass@2** = a test output counts if either of 2 attempts is correct (the Kaggle rule); with more than 2 samples it is the mean over all attempt pairs (attempts 0+1 shown as a0+a1). **Paired Δ** = run minus reference on the same test outputs (Kaggle pass@1, pp), 95% CI from a cluster bootstrap that resamples tasks (all test outputs of a task move together; 10,000 resamples).
- **Completeness rule (Table 1).** A run is complete when every counted sample has a record for all 167 pairs. Attempts lost to an API error are scored wrong; a sample with more than 1 such attempt counts as incomplete and the run goes to Table 2.
- **Tokens/attempt** = output (completion) tokens summed over all turns of an attempt, over attempts that returned. **Cost**: rec. = recorded per-call cost (`est_cost_usd` at off-peak list price incl. input, or OpenRouter's `cost_usd`); est. = output tokens × list price ($0.60/M Flash, $1.98/M Pro); rental = vast.ai box time from the README (footnoted).
- **Other sets.** pilot-26 = the first 15 tasks in sorted id order (26 pairs); dev-56 = E009's stratified dev set (`experiments/E009_tool_token_efficiency/dev_pairs.txt`); E004a-20 = E004's hard-biased 20-pair subset. Partial runs are scored on their covered pairs only (Kaggle: mean over covered test outputs; task-weighted: a task's score is over its covered pairs and only covered tasks are averaged).

## Key findings

Scores are Kaggle (pair-weighted) unless marked task-weighted; task-weighted values appear only where a finding is compared with ARC Prize's published numbers.

- **DeepSeek's new V4.1-Flash-1017 (E029) is more accurate and ~20% cheaper on the same harness; sub80s40 is the new best DeepSeek config.**
  - Same harness (sub80s40, persistent-v4), new model: Kaggle pass@1 73.1% / pass@2 82.0% over 2 samples against 66.5% / 76.4% for the old model's E009 sub80s40 (paired pass@1 +6.6 pp [+1.9, +11.4]; task-weighted 74.3% / 82.4%), at 31.7k tokens/attempt (−22%) and rec. $3.59 per sample. The old model's best pass@2 was E009/E011 sub96n's 79.0% at 45.7k tokens. On the 56 long-tail pairs it solves 79.5% (old sub80s40 63.1%).
  - At the tighter s20x60 budget the gain is within noise: 64.4% / 76.6% vs 61.4% / 75.4% (paired +3.0 pp [−1.2, +7.4]) at 26.7k tokens (−19%). The 80k budget is what lets 1017 turn its efficiency into accuracy on hard pairs.
  - A/B on the new model, lean2code ("decide in code" prompt + turns-left note + solve() fallback, persistent-v6): 72.8% / 81.4% at 32.9k tokens, −0.3 pp [−4.9, +4.4] vs plain sub80s40: a tie, so the prompt change buys nothing.
  - Trace reading (E029 strategy_reading.md / strategy_quant.md, not recomputed here): 1017 searches the same way with fewer dead ends; it thinks less per turn (largest turn 12.5k → 9.1k tokens) rather than taking fewer turns, and reaches a runnable candidate early enough that the 60k "submit now" note finds something to submit.
- **E030: a "Reasoning Effort: Minimal" header shortens Flash-1017 without losing accuracy; budget pressure, per-turn caps and prompt lines do not.**
  - DeepSeek implements its effort levels as a header at the start of the conversation (`high` and `max` prepend "Reasoning Effort: …" text, `low` adds nothing). `--effort-header minimal` sends one in the same style as a system message (terse notes, no restating or re-verifying, test ideas in code, submit once train passes). On sub80s40 it scores Kaggle pass@1 74.0% / pass@2 85.0% at 27.4k tokens/attempt (−14% vs plain sub80s40, paired pass@1 +0.9 pp [−3.7, +5.6]) and keeps the long-tail pairs (78.6%).
  - With the s20x60 budget it stacks: 68.0% / 79.0% at 23.3k tokens (−27%), against 64.4% / 76.6% at 26.7k without the header.
  - Budget pressure alone (s20x80: 67.4% / 79.6% at 28.7k, −10%) trims the long tail and loses hard pairs (68.8%). A per-turn thinking cap closed by a "test it in code now" nudge (`--cap-nudge`, 16k: 31.9k tokens) saves nothing: the model resumes the same deliberation in the next turn. Placement matters: the same brevity request as a user-prompt suffix (E009 `lean2brief`, old model) cost up to 14 pp.
- **Tools + lean2 prompt beat no tools for Flash; tools alone do not.** E004-GL (grid mode, lean2 prompt, low effort) scores pass@1 64.5% over 4 samples against 58.3% for no-tool E001d (3 samples), paired +6.2 pp [+0.2, +12.5], at 49.5k vs 55.7k tokens/attempt. ## Caveats

- **Public vs semi-private.** All full-set numbers are on the public evaluation set. ARC Prize's verified semi-private ARC-AGI-2 scores for DeepSeek V4.1 Flash are 72.9% (Max), 67.5% (High), 60.6% (Low) and 1.3% (None) [^arcprize], task-weighted; their public-eval table at Max marks 91/120 tasks solved. Our no-tool E001d (same prompt, max effort) fully solves 89/120 tasks (74.2%) with attempts 0+1 (other attempt pairs: 78 and 79) and scores 74.6% task-weighted pass@2 averaged over attempt pairs (73.3% Kaggle); per-task agreement with ARC Prize's Max column is 82–87% depending on the attempt pair. So our Flash numbers sit close to ARC Prize's public ones and should be read against V4.1's 72.9% semi-private, not against the older V4 Flash 0731 numbers. Qwen3.8-27B: 42.4% semi-private [^arcprize]; our public pass@2 for Qwen3.8 xhigh is 47.9% Kaggle (48.2% task-weighted). Table below.
- **Contamination.** The public set has been out since 2025, and in E004 traces Flash listed real ARC-AGI-2 eval task ids while trying to recall answers [^contam], so some memorisation is possible. But V4.1 Flash's public score at Max is only ~3 pp above its semi-private score, so any inflation of absolute Flash numbers looks small; comparisons within one model are not affected.
- **Sample noise is a few pp.** E004-GL's 4 samples span 62.3–68.3 (sd 2.6); E001d's span 51.5–63.5 (sd 6.1); across multi-sample DeepSeek runs the per-sample sd is 0.0–6.1 pp. Most paired CIs vs E004-GL include zero; only the losses (sub64a, s20x40, plain prompt) and the new model's gain (E029 sub80s40) are clearly significant.
- **Single samples.** Rows with 1 sample (grid-max, cap100, code mode, plain prompt, sub96s40, sub64a, E017 V1/V2, Nemotron, E024, E027) have no pass@2 and carry the full sample noise. pilot-26 and dev-56 numbers are noisier still (one test output moves the pilot by 3.8 pp on the Kaggle metric; one task by 6.7 pp task-weighted).
