2. Pilot Runs (By Hypothesis: Description, Result & Validating/Refuting Experiments)

Pilot H1: Keep the First 100%-Training-Passing Program Instead of Overwriting It
Result: YES — Validated (+1.5% to +2.9% on Hard Subsets, 0 Extra Tokens)

Inspiration: Imbue ARC-AGI-2 Evolution [https://imbue.com/blog/2026-02-27-arc-agi-2-evolution]
Hypothesis & Mechanism: When a model continues editing code after already passing 100% of training pairs (e.g. during a post-submission audit turn), it frequently introduces brittle special cases that break test generalization. Locking the first verified program in each attempt as primary (primary_first) and keeping later rewrites only as secondary backups improves both 2-attempt and 4-attempt accuracy without generating a single extra token.

Pilot H2: Auto-Check Every def solve(grid): & Return Exact Cell-by-Cell (row, col) Diffs + Repair Rounds
Result: NO at 16 Turns (−6.0%) · YES at 40 Turns (2× on hard_25, +6 New Tasks on dev_60)

Inspiration: Ryan Greenblatt [https://www.redwoodresearch.org/blog/getting-50-sota-on-arc-agi-with-gpt] · Poetiq [https://poetiq.ai/posts/arcagi_announcement/] [https://github.com/poetiq-ai/poetiq-arc-agi-solver] · Pivotools [https://pivotools.github.io/pivotools-quarto-blog/posts/agentic_coding_arc_agi/] · Imbue [https://imbue.com/blog/2026-02-27-arc-agi-2-evolution]
Hypothesis & Mechanism: Automatically executing every def solve(grid): block written in run_python against all training pairs and returning exact (row, col): expected E, got G diffs + repair instructions helps the model fix off-by-one bugs. Crucial finding: At the baseline 16-turn limit (EXP-02), auto-checking refutes the hypothesis (−5.96% on dev_60) because each diff triggers extra debugging turns until the model hits the 16-turn cap. Raising the turn limit to 40 turns (EXP-04, EXP-05, keeping the same 48k token cap) validates the hypothesis: it recovers the full score on dev_60 while solving 6 new tasks, and doubles live accuracy on hard_25 from 5.88% to 11.76%.

Pilot H3: Force Early Code Commitment at 12,000 Tokens (Explorer → Definer Deadline)
Result: NO Standalone (−10.7% pass@2) · YES in Hybrid Pool (+9.5% pass@2)

Inspiration: Explorer–Definer Pipeline [https://arxiv.org/abs/2607.06764]
Hypothesis & Mechanism: To prevent the model from spending all 48k tokens exploring without submitting code, we injected a prompt at 12,000 tokens requiring it to immediately write def solve(grid):. Standalone (EXP-03), this refutes the hypothesis: on hard tasks, 12k tokens is too early to know the true rule, so forcing code locks the model into debugging a flawed rule (−10.72% on dev_60, −11.43% on dev_hard_25). However, when pooled with 2 normal baseline attempts (EXP-08), it adds fast solutions on medium tasks (+9.52% on dev_60).

Pilot H5: 4 Half-Budget Attempts (4 × 24k) with Diverse Prompts / Object Summaries / TTA vs. 4 Full-Budget Attempts (4 × 48k)
Result: NO for 4 × 24k (Refuted — 24k Cuts Off Qwen) · YES for 4 × 48k (+17.7% pass@2 on hard_25)

Inspiration: Poetiq [https://github.com/poetiq-ai/poetiq-arc-agi-solver] · ARGA [https://arxiv.org/abs/2210.09880] · Product of Experts [https://lambdalabsml.github.io/Product-of-Experts-ARC-Paper/] [https://arxiv.org/abs/2505.07859] · BARC [https://arxiv.org/abs/2411.02272]
Hypothesis & Mechanism: We tested whether a 96k total token budget is better spent on 4 shorter attempts of 24k tokens each using (a) 4 diverse system prompts (EXP-11), (b) pre-computed connected-component/diff summaries (EXP-12), (c) 4 geometric rotations/flips (EXP-15), (d) 4 color permutations (EXP-16), or (e) all combined (EXP-17). All five 4 × 24k arms failed because on hard puzzles Qwen3.8-27B averages 37k–41k tokens per attempt before submitting a working program; capping at 24k truncated ~70% of attempts before completion. Keeping the full 48k per-attempt cap across 4 attempts (EXP-10B) jumped hard_25 from 11.76% to 29.41% (+17.65%).

Concrete Case Studies from the Reasoning Traces & Submitted Code

Case 1A: 1-Pixel Symmetry Assumption (31f7f899 — 288/289 Cells Right, 99.65%)

Stats: Attempts 1 & 3 both pass 100% of training pairs and predict the exact same 17×17 test grid with only 1 pixel wrong at (row=13, col=16): expected 8 (bg), got 7.

What the code & trace did wrong: The puzzle sorts vertical bars across a horizontal axis row (h_row=8) by their length. In all training examples, every vertical bar was symmetric above and below the axis (above == below). In the test input, the bar at col 0 had 5 cells above the axis and 4 cells below. Qwen collapsed each bar to a single symmetric scalar hl = max(above, below):

hl = max(above, below)  # collapsed (above=5, below=4) -> 5!
v_bars.append((c, color, hl))
...
for r in range(max(0, h_row - new_hl), min(H, h_row + new_hl + 1)):
    out[r, c] = color   # drew 5 below instead of 4 -> 1 extra pixel at (13,16)

Case 1B: 2-Example Phase Coincidence + Audit Rationalization (221dfab4 — All 4 Att Overfit Identically)

Stats: All 4 attempts pass 100% of the 2 training pairs in 8–14 turns (12k–20k tokens) and all 4 output the exact same wrong test grid (81.1% cell accuracy).

What the code & trace did wrong: A yellow marker (color 4) defines a vertical band where alternating stripes of color 4 and 3 are drawn every 2 rows. In both training examples, the marker was at the bottom such that anchoring the stripe phase to row 0 (if r % 6 == 0: color = 3) happened to match. In the test input, the 4-marker is at row 0, so row 0 must stay 4—yet Qwen overwrote the input's own 4-marker at row 0 with 3s and rationalized it during audit:

<think> The test input has background=8, object=6, marker at row 0, cols 7-13.
The output shows: Row 0 (phase 0): 3s at cols 7-13 (marker cols) - correct.
The output looks correct and general. CONFIRMED. </think>

Case 2: 3-Pixel Wire-Endpoint Edge Case (2b83f449 — 99.07% Cell Accuracy, 3 Pixels Off)

Stats: Attempt 2 passes 100% of training pairs (`train_pass=True`) and gets 319 / 322 cells right (99.07%), missing only (4,0), (4,15), and (10,1) (predicted 8 instead of 3).

What the code & trace did wrong: Instead of finding the unified topological rule for placing green (3) end-caps on horizontal wire segments, the model wrote a 45-line if/elif/else tree branching on len(segments) == 1 vs. is_first / is_last that fit all training examples by enumeration, missing 3 endpoint cells on a middle segment in the test grid.

Case 4: Solved in 10 Turns, Dropped by Arbitrary 1-1-1-1 Tie-Breaker (4c3d4a41 & b99e7126)

Stats: On 6 test pairs (3.82% of benchmark), one of the 4 attempts got the 100% exact test answer, but was not picked as attempt_1 or attempt_2.

Why the selector missed it: In b99e7126 and 4c3d4a41, all 4 attempts passed 100% of training pairs (`train_pass=True`) with 4 slightly different grids (a 1-1-1-1 vote tie). Notice which attempt was actually right:
